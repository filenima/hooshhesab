## تازه‌های v35 (جدیدترین)
- **تریال ۷ روزه (درخواست مالک)**: دورهٔ آزمایش رایگان از ۳ روز به ۷ روز کامل افزایش یافت — همهٔ متن‌ها، پلن‌ها، ایمیل‌ها و API یکسان به‌روز شدند (منبع واحد: `TRIAL_DAYS` در lib/plans.ts)
- **تخفیف ۵٪ سه‌روزه (درخواست مالک)**: پنجرهٔ «تخفیف ویژهٔ خرید اول» از ۲۴ ساعت به ۳ روز (۷۲ ساعت) گسترش یافت — تایمر شمارش معکوس، موتور تخفیف و فاکتور هماهنگ

- **دانش‌نامهٔ (RAG) دستیار از پیش تغذیه شد — صفر پیکربندی**: ۱۲۵+ سند (ماژول‌های محصول + پلن‌ها + قوانین مالیاتی/حسابداری ایران + تحقیق ۱۳ رقیب: هلو، سپیدار، راهکاران، محک، قیاس، ابرستان، هوفر، فینتو و...) — با `bun scripts/seed-rag.ts` قابل تکرار/به‌روزرسانی
- **جستجوی دانش‌نامه هوشمندتر**: ریشه‌یابی پسوندهای فارسی («انبارم» → «انبار») + امتیاز عنوان×۳
- **وویس فارسی کامل**: تشخیص گفتار (ASR) فارسی سمت سرور ✓ آزموده‌شده؛ خواندن پاسخ‌ها (TTS) با صدای فارسی خود مرورگر — اگر مرورگر صدای فارسی نداشته باشد پیام راهنمای شفاف فارسی (نه سکوت/خرابی)
- **۱۰۰ مقالهٔ جدید ۳۰۰۰+ کلمه‌ای در جریان**: اجرای بزرگ seo-worker (سقف از ۱۹ به ۱۲۰ افزایش یافت) — دکمهٔ «اجرای بزرگ» در پنل موتور سئو؛ مقاله‌ها با جدول + تصویر + FAQ + لینک داخلی تولید و در صف انتشار هر-N-روزه (قابل تنظیم در «زمان‌بند انتشار») قرار می‌گیرند
- **تب جدید سوپرادمین «سایت‌مپ و فایل‌های سئو»**: یک کلیک → بازسازی sitemap.xml + robots.txt + **llms.txt (استاندارد ربات‌های هوش مصنوعی: GPTBot/ClaudeBot/PerplexityBot)** + rss.xml + دانلود مستقیم هر فایل + آمار URL/حجم/آخرین بازسازی
- **امنیت**: `CRON_SECRET` الزامی شد برای endpointهای کرون (جلوگیری از اجرای عمومی)
- **ممیزی کامل سوپرادمین**: ۱۰۴ اندپوینت API تست شد — همهٔ سالم (گزارش: .qa-superadmin-apis.md)

## تازه‌های v32 (جدیدترین)

### سیستم بارکدخوان سراسری (درخواست بحرانی)
اسکن بارکد با دستگاه سخت‌افزاری حالا «در هر نقطهٔ برنامه» کار می‌کند — مثل هلو و تدبیر:
- موتور تشخیص اسکنر (`lib/barcode-scanner.ts`): الگوی تایپ فوق‌سریع + Enter، پاک‌سازی خودکار متن از فیلد فوکوس‌شده، بوق صوتی موفق/خطا (WebAudio)
- API جدید `GET /api/products/lookup?code=` — بارکد دقیق → SKU → پیشوند + موجودی و دسته
- **فرم فاکتور**: اسکن = افزودن فوری ردیف (با تبدیل ارز) + چیپ بازخورد + fallback از API برای کالای خارج از کش ۵۰۰۰تایی
- **صندوق POS**: اسکن حتی بدون فوکوس در فیلد بارکد + fallback API + ادغام خودکار در کش + حالت اسکن سریع پشت‌سرهم
- **لیست فاکتورها**: اسکن = باز شدن فرم فاکتور جدید با کالای اسکن‌شده
- **انبار**: اسکن = دیالوگ جستجو و تعدیل موجودی با همان کد
- **بقیهٔ صفحه‌ها**: کارت شناور «کالا یافت شد» با قیمت/موجودی + دکمهٔ «افزودن به فاکتور فروش»

### کارتخوان — دریافت خودکار مبلغ
- فایل پل آماده `public/pos-bridge/hoosh-pos-bridge.js` (نسخهٔ ۲، تک‌فایل Node بدون نصب) — **قابل دانلود از داخل خود برنامه** (ماژول اپ موبایل + راهنمای صندوق POS)
- سه حالت: `simulation` (تست، پیش‌فرض) / `manual` (کارتخوان معمولی — مبلغ بزرگ روی صفحه، کلید y/n/t) / `gateway` (درگاه درون‌ساز PSP: به‌پرداخت/سامان/آسان‌پرداخت/پاسارگاد)
- صندوق POS: با پرداخت «کارت‌خوان»، مبلغ خودکار به کارتخوان می‌رود — مشتری فقط کارت می‌کشد و رمز می‌زند؛ مرجع تراکنش در پیام موفقیت
- چیپ وضعیت زندهٔ «کارتخوان متصل ✓ / متصل نیست» بالای صندوق + راهنمای گام‌به‌گام اتصال سخت‌افزار (۳ مسیر)

### سازگاری لپ‌تاپ قدیمی (باگ «بج قرمز بدون متن»)
- ریشه: ارتفاع ثابت + overflow-hidden بج‌ها با فونت جایگزین (Tahoma) متن را کیلیپ می‌کرد → فیکس
- تشخیص خودکار مرورگر قدیمی (بدون color-mix/@layer) → حالت `legacy-mode`: متن‌های ریز ≥۱۲px، حذف بلور، بج‌های بدون کیلیپ
- بنر «مرورگر قدیمی» با inline-style (حتی با CSS شکسته نمایش داده می‌شود) + لینک دانلود Chrome
- حالت `lite-mode` برای سخت‌افزار ضعیف (رم ≤۲GB یا ≤۲ هسته): افکت‌های سبک

### فیکس پنل مقالات سوپرادمین
- خطای خاموشِ لیست خالی فیکس شد (رایج‌ترین علت: انقضای توکن — حالا پیام واضح + راهنما + دکمهٔ تلاش مجدد)
- آمار از کل مقالات (نه فیلترشده) + به‌روزرسانی خودکار هر ۴۵ ثانیه (مقالات جدید موتور سئو زنده ظاهر می‌شوند)

### دستیار هوشمند — ۱۰۰٪ آفلاین بدون پیکربندی
- `/api/ai/chat` هم حالا مثل agent-chat به موتور آفلاین fallback می‌کند (به‌جای خطای 503) — استریم و غیراستریم
- بج «موتور آفلاین هوش — بدون اینترنت، روی داده واقعی شما» روی پاسخ‌ها
- اجرای دستورات فارسی (فاکتور/مشتری/هزینه/یادآور/گزارش...) روی داده واقعی — بدون LLM

### نرخ طلا و سکه — همیشه کار می‌کند
- منبع جدید سبک `call1.tgju.org/ajax.json` (بدون اسکرپ) + گاردهای sanity متقابل (فیکس باگ واقعی: انس جهانی و یورو هر دو غلط پارس شده بودند)
- ویجت: ۱۰ نماد در دو گروه «طلا و سکه»/«ارزها» + آخرین به‌روزرسانی + دکمهٔ تازه‌سازی + بذر داده برای DB خالی
- کرون ارز فعال (هر ۱۰ دقیقه با ترافیک) + تیکر سکه امامی

### سیستم کد تخفیف پیشرفته + فیکس بحرانی خرید لایسنس
- مدل `Coupon` + `CouponRedemption` (درصد/مبلغ ثابت، سقف، حداقل سبد، محدودیت پلن، سقف استفاده، per-user، فقط اولین خرید، انقضا)
- تب «کدهای تخفیف» در سوپرادمین (آمار + ساخت + تولید خودکار کد + مدیریت) + فیلد کد تخفیف در چک‌اوت
- **باگ بحرانی فیکس شد**: خریدهای دارای تخفیف (حتی تخفیف خودکار ۵٪ اولین روز) هرگز لایسنس نمی‌گرفتند — چون verify مبلغ تخفیف‌خورده را با قیمت کامل پلن مقایسه می‌کرد!

### نسخه‌های آفلاین (PWA + اندروید + دسکتاپ)
- سرویس‌ورکر کامل (`public/sw.js`): صفحات بازدیدشده آفلاین + صفحهٔ آفلاین فارسی + API هرگز کش نمی‌شود
- پکیج سورس **اپ اندروید** (Capacitor + راهنمای فارسی ساخت APK) — دانلود از ماژول اپ موبایل
- پکیج سورس **اپ دسکتاپ** (Electron با منوی فارسی + راهنمای ساخت EXE + حالت ۱۰۰٪ آفلاین با سرور محلی)

## تازه‌های v31

### موتور سئو مستقل (seo-worker) — مقاله‌ها دیگر هرگز نیمه‌کاره نمی‌مانند
**مشکل:** تولید هر مقالهٔ ۳۰۰۰+ کلمه‌ای ۵-۸ دقیقه فراخوانی LLM می‌خواهد؛ اما سرور dev در سندباکس ۴GB با ترافیک کاربر هر ~۹۰ ثانیه memory-recycle می‌شد → اجرای ۱۹تایی همیشه می‌مرد (اجرای قبلی با done=0 گیر کرد).
**راه‌حل:** تولید به پروسهٔ مستقل کوچکِ `mini-services/seo-worker` (پورت ۳۰۳۵، ~۱۰۰MB) منتقل شد — کاملاً مصون از ری‌استارت‌های Next.js:
- منطق تولید مشترک در `lib/seo/article-core.ts` (پرامپت، LLM، مونتاژ، اعتبارسنجی — بدون وابستگی به Next.js)
- `lib/seo/article-generator.ts` حالا فقط رابط است: شروع/وضعیت از worker + fallback فایل مشترک `/tmp/hoosh-seo-runs.json`
- ازسرگیری خودکار نیمه‌کاره‌ها با dedupe (چند اجرای stale فقط «یک» جایگزین با بیشینهٔ باقی‌مانده می‌سازند)
- گارد زامبی برای bun --hot (حلقهٔ قدیمی بعد از reload بی‌صدا می‌میرد — دیگر دو حلقهٔ موازی LLM را دوبرابر نمی‌زنند)
- صبر ~۸ دقیقه‌ای روی 429 (بکوف ۱۰→۳۰→۶۰→۱۲۰→۲۴۰ ثانیه) + تلاش مجدد همان موضوع پس از ۹۰ ثانیه cooldown
- ذخیرهٔ پست با retry روی قفل SQLite + باطل‌کردن کش بلاگ سرور از راه دور (`?fresh=1`)
- dev-services.sh سرویس را idempotent بالا می‌آورد؛ /api/health زنده‌بودنش را تضمین می‌کند

## تازه‌های v20 (این نسخه)

### باگ‌فیکس‌های مهم
1. **ویرایشگر بلاگ سوپرادمین خالی بود** — API لیست، محتوای کامل HTML ۲۷ مقاله (~۶MB) را برمی‌گرداند و UI نمی‌توانست بارگذاری کند → حالا فقط متادیتا (۴۷KB)؛ محتوا هنگام باز کردن هر مقاله لود می‌شود
2. **پنل زمان‌بند انتشار بلاگ «—» نشان می‌داد** — درخواست‌ها بدون توکن احراز هویت بودند (401) → Bearer token اضافه شد
3. **لاگ ممیزی ضدتقلب گم می‌شد** — آبجکت به فیلد String در Prisma پاس می‌شد → JSON.stringify
4. **متن سئو صفحه اصلی «۱۴ روز تریال» می‌گفت** → «۳ روز» (سازگار با قانون جدید)
5. **حلقه کرش سرور در سندباکس** — دو باگ زیرساختی:
   - واچ‌داگ ۵ دقیقه برای «بوت لحظه‌ای کرش» صبر می‌کرد → حالا وجود پروسه را چک می‌کند
   - cache-warmer با واچ‌داگ مسابقه می‌گذاشت (self-start موازی → تداخل پورت) → خودکار‌سازی حذف شد + سوییچ توقف + گارد حافظه

- **صفحه سئویی `/calculators`** با WebApplication + FAQ + Breadcrumb اسکیما، مقاله ۳۱۰۰+ کلمه‌ای، لینک‌سازی داخلی
- **ادغام در لندینگ** (`/`) به‌عنوان سکشن قابل مدیریت از ویرایشگر بصری سایت (registry + ترتیب)
- افزودن به **sitemap.xml** (۲۱۶ URL) + منوی هدر + لینک از SeoHero

## نکته مهم محیط توسعه
سندباکس ۴GB است؛ کامپایل‌های سنگین (پنل سوپرادمین پس از تغییر کد) ممکن است OOM بزنند — واچ‌داگ خودکار ریکاور می‌کند (لاگ: `watchdog.log`). در سرور واقعی با RAM کافی این مسئله وجود ندارد. برای توقف cache-warmer در محیط کم‌حافظه: `touch /tmp/hoosh-warmer-paused`

## کرون‌جاب‌ها (سرور واقعی — سندباکس کرون سیستمی ندارد)
سندباکس کرون سیستمی ندارد؛ endpointهای زیر self-throttling طراحی شده‌اند تا از هر سرویس کرون خارجی (crontab سرور، UptimeRobot، GitHub Actions) صدا زده شوند. اگر `CRON_SECRET` در `.env` تنظیم شود، همهٔ مسیرهای `/api/cron/*` (به‌جز currency که داخلی است) بدون هدر `x-cron-secret` پاسخ 401 می‌دهند.

| مسیر | توصیهٔ زمان‌بندی | کار |
|---|---|---|
| `/api/cron/newsletter-weekly` | پنجشنبه ۰۹:۳۰ تهران | شمارهٔ هفتگی خبرنامه (پست‌های ۷ روز اخیر) به مشترکین فعال — گارد ضدتکرار ۶ روزه + ثبت در «شماره‌های ارسال‌شده» پنل سوپرادمین |
| `/api/cron/publish-scheduled` | هر ۳۰ دقیقه (`?autoschedule=1` برای نوبت‌دهی خودکار) | انتشار بلاگ‌های زمان‌بندی‌شده |
| `/api/cron/push-schedules` | هر ساعت | ارسال پوش‌های زمان‌بندی‌شده |
| `/api/cron/2fa-reminders` | هر ساعت | یادآوری ورود دوعاملی |
| `/api/cron/seo-content` | هر ۶ ساعت | تریگر موتور تولید مقالهٔ سئو |

نمونهٔ crontab سرور واقعی (CRON_SECRET=... در `.env`):
```cron
30 6 * * 4  curl -s -X POST -H "x-cron-secret: SECRET" https://SITE/api/cron/newsletter-weekly # پنجشنبه ۰۹:۳۰ تهران
*/30 * * * * curl -s -X POST -H "x-cron-secret: SECRET" https://SITE/api/cron/publish-scheduled?autoschedule=1
0 * * * *   curl -s -X POST -H "x-cron-secret: SECRET" https://SITE/api/cron/push-schedules
```
